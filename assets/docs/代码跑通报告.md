## 一、这个"检索代码"是什么

BRepNet（Autodesk Research，CVPR 2021）是一个面向 CAD 边界表示（B-Rep）的拓扑消息传递网络，
**原始任务是逐面语义分割，不是模型级检索**。但官方仓库附带了一个 `similarity_search` notebook，
演示了「选几个查询面 → 与候选模型逐面找最近距离 → 求和 → 排序」的检索评分方法：

```
score(Q, T) = Σ_i  min_j  || q_i - t_j ||₂
```

本项目的**检索代码 `brepnet_retrieval.py`** 就是把这段官方 notebook 的评分逻辑，
工程化为一个**独立、可测试、可批量统计、可重复运行**的 Python 实验包。

## 二、为什么需要它

官方 notebook 有三个工程缺陷，不能直接拿来汇报 Top-1：

| 问题 | 官方 notebook | 本项目处理 |
|------|--------------|-----------|
| Top-k 排序 | `np.argpartition` 只保证选出最小 k 个，**不保证显示顺序** | 完整稳定排序，输出顺序即真实排名 |
| 单面模型 | 需手工把一维数组扩成二维 | 加载函数统一保证 `faces × features` |
| 结果留存 | 以 notebook 输出为主 | 导出 JSON + 查询汇总 CSV + Top-k CSV |

## 三、缺了它会是什么结果

**缺了它，你无法对外复现、也无法验证检索链路是否正确贯通。** 具体表现为：

1. 只能拿着官方 notebook 的截图，但它的 Top-k 输出顺序可能是乱的，汇报 Top-1 没有说服力；
2. 每次要复现都得重新手写一遍评分逻辑，没有测试兜底，容易出错；
3. 无法批量统计「每个模型是否检索到自己」的命中率，也就无法形成可复核的实验结果文件。

有了它，就有了一个**验收门槛**：检索链路（读取嵌入 → 距离计算 → 排序 → 统计导出）是否贯通，
一次命令就能验证。

## 五、结论与边界

**结论**：检索代码链路已跑通。合成数据上自身 Top-1 为 100%、自身得分全为 0、平均自身排名 1.000，
与报告的数学预期（同一嵌入自比较距离为 0）完全一致。

**必须对外强调的边界**：自身检索本质是 **sanity check（通路自检）**。它只证明
「读取嵌入 → 距离计算 → 排序 → 统计」这条代码链路正确，**不证明 BRepNet 对陌生真实零件有良好的泛化检索能力**。
通过后，项目才具备继续做「真实 STEP 推理 → 去自身检索 → 有标签评估」的基础。

## 六、如何在 VSCode 里运行

1. 用 VSCode 打开目录 `brepnet_retrieval/`；
2. 确认 Python 解释器（建议 3.9+），终端执行：
   ```bash
   pip install -r requirements.txt
   ```
3. 跑合成演示：
   ```bash
   python brepnet_retrieval.py demo --output-dir experiment_runs/synthetic_demo --top-k 5
   ```
4. 跑测试：
   ```bash
   python -m unittest discover -s tests -v
   ```

## 七、下一步（真实 STEP 推理）

当前跑通的是**检索层**。真实「STEP → 面嵌入 → 自身检索」闭环还需要在 BRepNet 旧版环境
（Python 3.7 + PyTorch 1.7.1 + pythonocc-core 7.5.1）中，把 25 个官方 STEP 示例推理成
`.embeddings` 文件，再执行：

```bash
python brepnet_retrieval.py evaluate \
    --embeddings-dir <path/to/embeddings> \
    --output-dir real_results --faces all --top-k 5
```
